# תכנית עיצוב: דף הפרגולות, בנייה מחדש לפי הסקילים

בדיקת A/B של שלושה סקילים. לא עולה לאוויר. הקופי אינו משתנה מילה, ולכן אין כאן שום החלטה על ניסוח.
**סדר העדיפויות:** `visual.md` של באים בטוב וקובץ הקופי גוברים על `frontend-design`. החופש שלי הוא בפריסה, ב-hero, בתנועה ובמבנה.

## 1. נושא, קהל ותפקיד

- **נושא:** פרגולות עץ לבתים פרטיים, קמפיין "אחרי סוכות". החומר: עץ, צל, חצר.
- **קהל:** בעל בית (בני זוג מחליטים יחד) שפתח את הדף מהמודעה בנייד, ביד אחת. חלק מהם לא ראו את המודעה, ולכן ה-hero מסביר מי אנחנו.
- **תפקיד הדף:** להביא לחיצה על וואטסאפ (ערוץ ראשי) או טופס קצר (משני).
- **הדימוי המארגן:** הצל שפרגולה מטילה. קורות מקבילות והפסים שהן מציירות על הקרקע.

### גופנים (כולם מ-`visual.md` §2)

- **כותרות: Heebo.** כאן הוא נושא את האישיות: ה-h1 מחולק לשני משפטים במשקלים מנוגדים (300 ו-700), והמספרים בשלבים ב-200 גדולים.
- **גוף: Assistant**, 400 ו-600, `1rem`, שורה 1.7.
- סולם: h1 עד 3rem, h2 עד 2.4rem (בנייד 1.8rem), h3 1.4rem, גוף 1rem. קטן מ-1rem אין.
- אין `letter-spacing`, `italic`, `uppercase`.

## 3. פריסה

**מושג:** דף של קורות. קורות אופקיות בלי קישוטים, ובתוכן אזורים בעלי דפוסים שונים לפי סוג התוכן, לא תבנית אחת שחוזרת.
יישור: טקסט `start` (ימין) בכל הדף. אין מרכוז, אין justify.

### Hero (המקום היחיד שבו מושקעת הנועזות)

```
דסקטופ (RTL: הטקסט מימין)                       נייד
+---------------------------------------+      +----------------+
| ////  פסי צל אלכסוניים ברקע  ////     |      | logo           |
|  [התמונה]            הסוכה צריכה      |      | הסוכה צריכה    |
|  [slide1 ]           להחזיק שבוע.     |      | להחזיק שבוע.   |
|  [      ]            פרגולה צריכה     |      | פרגולה צריכה   |
|  [      ]            לעבור חורף.      |      | לעבור חורף.    |
|                      about / sub      |      | about / sub    |
|                      [וואטסאפ][טופס]  |      | [וואטסאפ]      |
|                      לעבודות שלנו    |      | [טופס]         |
+---------------------------------------+      | [תמונה]        |
| trust 1   |  trust 2   |  trust 3     |      | trust x3 (שורות)|
+---------------------------------------+      +----------------+
```

- ה-h1 בשני משפטים: הראשון ב-300, השני ב-700. החלוקה לפי משפט, לא הדגשת מילה בודדת.
- פסי הצל: `repeating-linear-gradient` באגוז בשקיפות 6%. תנועה אחת: בטעינה הם גולשים פנימה פעם אחת (1.6 שניות). זו כל התנועה שאינה תגובה לפעולה. מבוטלת תחת `prefers-reduced-motion`.
- ה-CTA הראשי בנייד נראה בלי גלילה (או שהבועה הצפה זמינה).

### איך זה עובד

רשימה מסודרת ב-`<ol>` עם ציר אנכי. מספור מוצדק כי ארבעת השלבים הם רצף אמיתי. המספרים נוצרים ב-CSS (`counter`), לא נכתבים בטקסט.
בדסקטופ: הכותרת בעמודה אחת (דביקה), השלבים בשנייה. הערת ההיתר בשלב 2 מקבלת קו צד, כדי שיהיה ברור שהיא נפרדת מאישור הקונסטרוקטור.

### למה לבנות איתנו

סקשן על רקע אלון בהיר. **לא שלושה כרטיסים.** שלוש שורות של "ספר חשבונות": כותרת בעמודה אחת, גוף בשנייה, קו חול בין השורות. אין צל, אין כרטיס.

### עבודות שבנינו

מוזאיקה אסימטרית של ארבע תמונות אמיתיות. אחת גדולה על שתי שורות, ושלוש סביבה. בנייד: רחבה, זוג, רחבה. אין כיתובים (הקופי לא נותן). אין הגדלה (לא נדרשת).

### שאלות נפוצות

`<details>` מקורי, בלי JS. הפלוס מסתובב ל-x בפתיחה (תנועה שעונה לפעולה). דסקטופ: כותרת בצד, רשימה בצד.

### CTA וטופס

סקשן כהה. עמודה אחת: כותרת, שורות הקופי, תווית וכפתור וואטסאפ (ערוץ ראשי). עמודה שנייה: טופס בכרטיס לבן, **הכרטיס היחיד בדף** שיש לו צל (הצל מ-`visual` §4).

```
+---------------------- dark ----------------------+
|  h2 + cta.text + cta.next      +--------------+  |
|  (הפגישה בלי עלות.)            |  form card   |  |
|  מעדיפים לכתוב?                |  שם / טלפון  |  |
|  [שלחו לנו וואטסאפ]            |  יישוב/פרטים |  |
|                                |  הודעת יידוע |  |
|                                |  [שליחה]     |  |
|                                +--------------+  |
+--------------------------------------------------+
```

### בועת וואטסאפ

צפה, ב-RTL בצד שמאל (`inset-inline-end`). לא נפתחת לבד. Escape סוגר.

## 4. עקרונות

1. **נועזות במקום אחד:** ה-hero (טיפוגרפיה במשקלים מנוגדים, פסי צל, תמונה אמיתית). כל השאר שקט.
2. **המבנה מקודד מידע:** מספרים רק ברצף אמיתי; קווים רק כשיש הפרדה בין פריטים; כרטיס אחד, ולכן הוא בולט.
3. **אין תוויות עליונות** מעל כותרות, אין מפרידי נקודות שאינם מהקופי, אין חץ בסוף קישור.
4. **פינות חדות** (0 עד 4px), כמו באתר. רק הבועה עגולה.
5. **קריא בשמש:** גוף 1rem, ניגודיות גבוהה, יעדי מגע 44px ומעלה, פוקוס של 3px.

| ה-h1 עם מילה אחת בצבע דבש | הסימן הגנרי של הדגשת מילה בודדת | חלוקה לשני משפטים במשקלים 300/700, בצבע אחד |

| חץ בסוף כל קישור וכפתור | סימן גנרי | הוסר. הכפתורים הם טקסט הקופי בלבד |
| גלריה של ארבע תמונות שוות בגריד 2x2 | אחידות משעממת | מוזאיקה אסימטרית עם תמונה אחת דומיננטית |
| שגיאות באדום | אין אדום ב-`visual` ושגיאה לא רק בצבע | אגוז כהה, מסגרת עבה, קו צד וטקסט |

## 6. נקודות שבהן סקיל פוגש מגבלה

- **`frontend-design`: "אל תבחר בפלטה דיפולטית" מול `visual`.** הפלטה נעולה. החופש נוצל בפריסה ובטיפוגרפיה.
- **`frontend-design`: "More on writing in design"** לא חל. אין ניסוח חדש.
- **`israel-compliance-checklist` מול הקופי:** הודעת היידוע בקופי (`form.privacy`) קצרה מהנדרש. סומן `MISSING COPY` ב-HTML ודווח.
