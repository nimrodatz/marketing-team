# קמפיין חדש: $ARGUMENTS

אתה המנכ"ל, והפקודה רצה בסשן הראשי. התוצר: **בריף אחד** ב-`vault/Content Briefs/<topic>.md`,
עם `client`, `channel` ו-`run`, שאפשר למסור לקופירייטרית כמו שהוא. **הפקודה לא מריצה את
הפייפליין.** היא נגמרת בבריף ובעצירה.

## 0. הלקוח

1. הרץ את שלב 1 של `obsidian-vault-workflow`. הנושא: ה-`<topic>` של הקמפיין.
2. **`clients/<client>/client.md` לא קיים: עצור**, והצע `/new-client <client>`. אל תפתח לקוח מתוך קמפיין.
3. קרא את `client.md` במלואו, ואת קובץ ה-`facts` שהוא מצביע עליו.
4. **לקוח בסטטוס `טיוטה`:** ממשיכים, ואומרים את זה בראש הדיווח. `<placeholder>` שנשאר בקובץ
   `facts` או `icp` יעצור את הקופירייטרית, ולכן מונים אותם עכשיו ולא בשלב 1.

## 1. ה-topic ומספר הריצה

- **ה-topic:** אנגלית, אותיות קטנות ומקפים. הוא שם כל הקבצים בריצה.
- **בריף בשם הזה כבר קיים ללקוח אחר: עצור.** שני לקוחות לא חולקים topic, כי יומן הפרסום
  סופר ריצות לפי topic בלבד.
- **בריף בשם הזה קיים לאותו לקוח:** זו ריצה חוזרת ולא קמפיין חדש. שאל אם לעדכן את `run` בבריף
  הקיים או לפתוח topic אחר. אל תדרוס בריף.
- **`<N>`:** ספור ב-`vault/Publishing Log/` את הקבצים `<topic>-run-*.md`, והוסף 1. בדוק מולו גם
  את `output/<client>/marketing/*-<topic>-run*-copy.md`. **המספרים לא מסכימים: עצור והראה את
  שניהם.** ריצה שרצה ולא נרשמה היא בדיוק הבאג שהמספור הזה סוגר.

## 2. השאלות

שאל רק מה שחסר ב-`$ARGUMENTS` ובתיק הלקוח. **סבב אחד**, וכל שאלה עם ברירת המחדל שלה.

| שדה | חובה | הערות |
|---|---|---|
| **`channel`** | ✱ | `outbound` · `group-post` · `landing` · `paid-social` · `paid-search`. **חייב להופיע ב-`channels` של הלקוח.** לא מופיע: עצור. הוספת ערוץ ללקוח היא החלטה של נימרוד |
| **ההצעה** | ✱ | מה הקמפיין מציע, ומה ה-Ask. **רק שירות שקיים בקובץ ה-`facts`.** ה-Ask הוא ברירת המחדל ב-playbook של הלקוח, אלא אם נימרוד משנה |
| **תקציב** | בממומן ✱ | סכום ותקופה. באורגני: "אין" |
| **הקהל** | ✱ | תת-סגמנט אחד מקובץ ה-`icp`, וטמפרטורה: חם, פושר או קר |
| **ערך `world`** | | מקובץ ה-`world` של הלקוח. ריק: ברירת המחדל במניפסט |
| **מחיר בתוצר** | | ברירת המחדל: לא. כן: רק מחיר שכתוב בקובץ ה-`facts` |
| **מספר תמונות** | | ברירת המחדל 0. יותר מ-0 דורש אישור עלות נפרד לפני שלב 3 |
| **מחוץ לסקופ** | | הטבות, הבטחות ונושאים שלא יופיעו באף תוצר |

> [!warning] ערוץ ממומן עדיין לא נבנה
> `paid-social` ו-`paid-search` נכנסים לבריף, אבל **הקמפיינר עדיין מייצר רק ערכת Outbound.**
> ערכת המודעות היא שלב 4 ב-[[multi-client-engine]], והוא לא בוצע. בריף ממומן רץ היום רק
> בשלבים 1, 3 ו-4, **ושלב 2 עוצר.** כל מודעה, כשתיבנה, נוצרת `PAUSED`.

## 3. כתיבת הבריף

1. **העתק את `vault/Content Briefs/_template-brief.md`** ל-`vault/Content Briefs/<topic>.md`,
   ומלא. ה-frontmatter נושא את `client`, `channel` ו-`run`, כי משם הסוכנים קוראים אותם.
2. **כל עובדה בבריף מגיעה מתיק הלקוח.** מחיר, שם שירות או הוכחה שאינם שם לא נכנסים לבריף.
   מה שנימרוד מוסיף בראיון ואין לו מקור נרשם כשאלה פתוחה בבריף, ולא כעובדה.
3. הוסף שורה לבריף ב-`vault/Content Briefs/_index.md`.
4. **הרץ את בדיקת העובדות:** `pwsh -File scripts/verify-site-facts.ps1 -Client <client>`.
   דריפט: עצור והראה את הפער. בלי `facts-check.json` הסקריפט מדלג ומדווח, וזה תקין.

## 4. הדיווח, והעצירה

1. הלקוח, הסטטוס שלו, ה-topic, `run<N>`, הערוץ.
2. **מה יעצור את הפייפליין**: placeholders בתיק, לקוח בטיוטה לפני שלב 3, ערוץ ממומן לפני שלב 2.
3. **השמות שהריצה תייצר**, לפי מוסכמת השמות ב-`CLAUDE.md`, תחת `output/<client>/`.
4. **נתיב מלא לבריף**, מ-`C:\`, בבלוק.

**עצור כאן.** שלב 1 מתחיל רק כשנימרוד אומר.

בסוף: שלב 2 של `obsidian-vault-workflow`. הבריף החדש הוא קובץ נושא בפני עצמו, עם Session Log משלו.
